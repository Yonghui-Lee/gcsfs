## 2024-05-18 - Fast string parsing over Standard Library URLs in Hot Paths
**Learning:** `urllib.parse.urlsplit` and `parse_qs` introduce significant overhead when called on every file operation (like in `_split_path`). Native string methods (`.find()`, slicing) with early exits (`if "#" not in path and "?" not in path`) are vastly faster for specific standard formats (like integer-only generation IDs) and bypass heavy list/dict allocations.
**Action:** When working on core file system operations or routing hot paths, prefer native string operations over standard library URL parsing tools if the expected format and fallback behavior can be explicitly managed. Avoid allocating `set()` objects dynamically in hot functions (`_coalesce_generation`) unless absolutely necessary for complex merging or formatting.
